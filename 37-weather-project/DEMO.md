# Демонстрация проекта

1. Создать .env из .env.example и задать два разных случайных пароля. Запустить docker compose up -d --build. Дождаться SUCCESS rows=180 в логах pipeline.
2. Выполнить создание дашборда из README. Открыть http://localhost:3000 и войти в учебный аккаунт otus@example.com со своим METABASE_PASSWORD.
3. Показать общий дашборд: 180 city-days, температура двух городов, осадки, месячная сводка. Выбрать Berlin: 90 city-days и только его данные на всех пяти карточках.
4. Показать schema.sql: raw сохраняет источник и происхождение, staging хранит историю без дублей, mart выбирает последние 90 дней и рассчитывает показатели, audit фиксирует запуски.
5. Показать pipeline.py: таймаут/повторы HTTP, проверки дат и единиц, одна транзакция на два города, upsert, успешный или failed аудит, ежедневный цикл.
6. Повторить однократную загрузку командой docker compose run --rm --no-deps pipeline python pipeline.py --once. Проверить отсутствие дублей через verify_project.py.
7. Запустить test_validation.py и test_transaction.py командами docker compose run --rm --no-deps -v "${PWD}:/app" pipeline python ИМЯ_ТЕСТА. Второй тест намеренно ломает ответ второго города и доказывает откат первой записи; запись failed в audit ожидаема.

Показатели скриншотов относятся к прогону 22.11.2026. На новую дату суммы погоды могут измениться. Это reanalysis ERA5, температура midpoint не равна измеренной среднесуточной температуре. Семь последних дней исключены из-за задержки архива.

После демонстрации: docker compose stop. Данные сохраняются. Для следующего просмотра: docker compose up -d.
